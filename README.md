# Memex — onchain-терминал с аналитикой и PAPER-агентом

Мультичейн-терминал (Solana, BNB Chain, Base, Ethereum) с рыночной аналитикой,
смарт-кошельками, копитрейдингом и автономным агентом в строго изолированном
PAPER-режиме.

## Что уже работает

| Блок | Статус |
|---|---|

| Performance fee 10% + альтернативная модель high-water mark | готово, покрыто тестами |
| Логика лимиток, стопов, тейков, trailing stop | готово, покрыто тестами |
| Правила копитрейдинга (сайзинг, риск-фильтры, лимиты) | готово, покрыто тестами |

| REST API: auth, ордера, PAPER-агент, копитрейд, портфель, админка | готово |
| Воркеры: лимитки, цены, исполнение копий | готово |
| Автономный OKX Signal агент Phase 3 | paper-only, Fixed + Autopilot, `/agent` |
| Фронтенд: терминал, агент, радар, смарт-кошельки, портфель | готово |
| Адаптер Solana (Jupiter): котировки, цены, балансы | готово |
| Адаптер EVM (0x): котировки, цены, балансы | готово |
| **Подпись и отправка транзакций в mainnet** | **заглушка — см. ниже** |
| Phase 4 contracts/mock pipeline | foundation готов, реальные адаптеры заблокированы |
| Депозиты/выводы on-chain, KYC-провайдер | интерфейсы готовы, production providers не подключены |

Проект запускается в режиме `EXECUTION_MODE=paper`: весь путь ордера отрабатывает
по реальным котировкам агрегаторов, но транзакции в сеть не уходят. Это позволяет
проверить всю экономику до подключения денег.

Устройство и жёсткая изоляция первого автономного агента описаны в
[`docs/paper-agent.md`](docs/paper-agent.md).
Безопасный фундамент будущего LIVE и точная таблица блокеров описаны в
[`docs/phase4-readiness.md`](docs/phase4-readiness.md).

## Запуск

```bash
cp .env.example .env
# сгенерировать ключи
echo "JWT_SECRET=$(openssl rand -base64 48)" >> .env
echo "KMS_LOCAL_MASTER_KEY=$(openssl rand -base64 32)" >> .env

docker compose up -d          # postgres + redis
npm install
npm run db:push
npm run db:seed

npm run dev:api               # http://localhost:4000
npm run dev:web               # http://localhost:3000
npm run worker -w @memex/api  # воркеры лимиток, цен и копий
```

Тестовые аккаунты после сида:

| Роль | Логин |
|---|---|
| Админ | admin@memex.local |
| Лидер копитрейдинга | leader@memex.local |
| Пользователь | user@memex.local |

Пароль печатается при выполнении `npm run db:seed`. Локально это
`DevPassword123!`; при подключении к облачной базе генерируется
случайный, чтобы публичный стенд не имел общеизвестного админа.
Задать свой: `SEED_PASSWORD=... npm run db:seed`.

## Структура

```
packages/core/     чистая бизнес-логика без БД и сети — здесь живут все деньги
  money.ts         Decimal-арифметика, 40 знаков точности
  position.ts      учёт позиции по средневзвешенной стоимости
  fees.ts          performance fee 10%, high-water mark
  orders.ts        срабатывание отложенных ордеров, валидация котировок
  copy.ts          правила копирования сделок
  risk.ts          скоринг мем-коинов
apps/api/
  chains/          адаптеры Solana (Jupiter) и EVM (0x)
  services/        исполнение, балансы, копитрейдинг
  modules/         HTTP-роуты
  workers/         фоновые процессы
apps/web/          Next.js 15, терминал и админка
prisma/schema.prisma
```

Вся денежная логика вынесена в `packages/core` намеренно: её можно прогнать
на исторических данных, покрыть тестами и проверить без поднятия базы.
Ошибка в расчёте комиссии — это спор с пользователем и возврат средств,
поэтому эта часть тестируется отдельно от инфраструктуры.

## Что нужно доделать до боевого запуска

1. **Подпись транзакций.** `apps/api/src/services/execution.ts::signPayload` —
   заглушка. Нужны `@solana/web3.js` (nacl detached) и `viem` (EVM).
2. **Nonce-менеджер для EVM.** Параллельные сделки с одного кошелька без него
   вытесняют друг друга.
3. **Депозиты.** Индексатор входящих транзакций → зачисление на баланс.
4. **Выводы.** Очередь + 2FA + ручное подтверждение выше порога.
5. **KYC/AML.** Sumsub или Persona, скрининг адресов (Chainalysis/TRM).
6. **Cold storage.** Автоматический перевод остатка выше `HOT_WALLET_MAX_USD`.
7. **Юридическая структура.** См. `docs/LEGAL-RISK.md` — при выбранной
   кастодиальной модели это блокирующий пункт, а не пожелание.
