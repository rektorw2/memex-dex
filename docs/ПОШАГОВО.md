# Пошаговая инструкция

Две независимые части. Часть А — запустить в облаке бесплатно.
Часть Б — купить домен и привязать. Часть Б можно отложить: сайт будет
работать и без домена.

---

# Часть А. Запустить в облаке

Три сервиса: база, бэкенд, фронтенд. Примерно 20 минут.

## Шаг 1. База данных — Neon

1. Открыть [neon.tech](https://neon.tech), войти через GitHub
2. **Create project**: имя `memex`, регион **Europe (Frankfurt)**
3. Нажать **Copy snippet** под строкой подключения. Именно кнопку —
   в самом поле пароль скрыт звёздочками.

   Скопированная строка выглядит так:
   ```
   postgresql://neondb_owner:ПАРОЛЬ@ep-noisy-bar-b19azsb5.c-5.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

**Понадобятся две строки, отличающиеся одним словом.**

| Какая | Хост | Для чего |
|---|---|---|
| Прямая | `ep-noisy-bar-b19azsb5.c-5…` | создание таблиц, миграции |
| Через пул | `ep-noisy-bar-b19azsb5-pooler.c-5…` | рабочие запросы приложения |

Вторая получается из первой добавлением `-pooler` сразу после
идентификатора, перед первой точкой. Больше ничего менять не нужно.

Зачем так: пул позволяет держать много соединений на бесплатном тарифе,
но не поддерживает механизмы, на которых работают миграции Prisma.
Поэтому таблицы создаём напрямую, а приложение работает через пул.

4. Создать таблицы и тестовые данные — здесь **прямая** строка:

   ```bash
   export DIRECT="postgresql://neondb_owner:ПАРОЛЬ@ep-noisy-bar-b19azsb5.c-5.eu-central-1.aws.neon.tech/neondb?sslmode=require"

   DATABASE_URL="$DIRECT" npm run db:push
   DATABASE_URL="$DIRECT" npm run db:seed
   ```

   Вторая команда напечатает пароль от тестовых аккаунтов.
   **Скопируйте его — второй раз он не покажется.**

Обе строки сохраните, они понадобятся на следующем шаге.

## Шаг 2. Бэкенд — Render

1. Открыть [render.com](https://render.com), войти через GitHub
2. **New → Blueprint**
3. Выбрать репозиторий `rektorw2/memex-dex`.
   Если его нет в списке — **Configure account** и дать Render доступ
   к репозиторию (он приватный, поэтому доступ нужно выдать явно)
4. Render прочитает `render.yaml` и предложит создать сервис `memex-api`.
   Он попросит заполнить две переменные:

   | Переменная | Что вписать |
   |---|---|
   | `DATABASE_URL` | строка **с `-pooler`** |
   | `DIRECT_DATABASE_URL` | строка **без `-pooler`** |
   | `CORS_ORIGINS` | `https://rektorw2.github.io` |
   | `ZEROX_API_KEY` | оставить пустым |

   `CORS_ORIGINS` — **без** `/memex-dex` в конце. Браузер передаёт только
   имя сайта, без пути. Ошибка здесь даёт пустые экраны без единой
   ошибки в логах.

5. **Apply**. Первая сборка идёт 5–10 минут.
6. Когда статус станет **Live**, скопировать адрес сервиса сверху страницы.
   Он будет вида `https://memex-api.onrender.com`

Проверить, что бэкенд жив:

```bash
curl https://memex-api.onrender.com/health
```

Ожидаемый ответ: `{"ok":true,"mode":"paper",...}`

## Шаг 3. Фронтенд — GitHub Pages

В репозитории на github.com:

1. **Settings → Pages → Source** → выбрать **GitHub Actions**
2. **Settings → Secrets and variables → Actions** → вкладка **Variables**
   → **New repository variable**:

   | Имя | Значение |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | `https://memex-api.onrender.com/api/v1` |

   Обратите внимание на `/api/v1` в конце — без него все запросы
   получат 404.

3. **Actions** → слева **Deploy web to GitHub Pages** → **Run workflow**

Через пару минут сайт будет по адресу:

```
https://rektorw2.github.io/memex-dex/
```

## Шаг 4. Проверить

Открыть сайт, войти как `admin@memex.local` с паролем из шага 1.

**Первый вход займёт около минуты.** Бесплатный Render засыпает после
15 минут простоя, и первый запрос будит контейнер. Интерфейс покажет
подсказку вместо ошибки. Это не поломка.

Если войти не удалось, проверьте связку одной командой:

```bash
curl -I -H "Origin: https://rektorw2.github.io" \
  https://memex-api.onrender.com/health | grep -i access-control
```

Если строка `access-control-allow-origin` не появилась — значит
`CORS_ORIGINS` на Render заполнен неверно. Это причина примерно всех
случаев «сайт открывается, но ничего не работает».

# Часть Б. Свой домен

Нужен, только если хочется красивый адрес вместо `rektorw2.github.io/memex-dex/`.
На работу приложения не влияет.

## Шаг 5. Купить

Проверить занятость и купить можно у любого регистратора.
Ориентир по ценам за первый год:

| Регистратор | `.com` | Комментарий |
|---|---|---|
| [Cloudflare](https://dash.cloudflare.com) | ~$10 | продаёт по себестоимости, без наценки при продлении |
| [Namecheap](https://namecheap.com) | ~$10 | дешевле первый год, дороже продление |
| [Porkbun](https://porkbun.com) | ~$10 | бесплатная защита данных владельца |

Cloudflare удобнее остальных: там же управление DNS, и он умеет
запись ALIAS для корневого домена — она понадобится на шаге 6.

Проверить `memexdex.com` можно прямо в поиске регистратора или командой:

```bash
whois memexdex.com
```

Если ответ содержит `No match for domain` — свободен.

## Шаг 6. Настроить DNS

Раскладка: сайт на самом домене, бэкенд на поддомене `api`.

В панели регистратора добавить три записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `rektorw2.github.io` |
| CNAME | `api` | `memex-api.onrender.com` |

Четыре A-записи с одинаковым именем `@` — это не ошибка, так и нужно:
это адреса серверов GitHub Pages, и они резервируют друг друга.

## Шаг 7. Привязать домен к сайту

1. GitHub: **Settings → Pages → Custom domain** → вписать `memexdex.com`
   → **Save**
2. Дождаться зелёной галочки проверки DNS (от 10 минут до часа)
3. Поставить галочку **Enforce HTTPS**
4. **Settings → Secrets and variables → Actions → Variables** →
   добавить ещё одну:

   | Имя | Значение |
   |---|---|
   | `PAGES_CUSTOM_DOMAIN` | `memexdex.com` |

   Эта переменная убирает префикс `/memex-dex` из путей. Без неё сайт
   на своём домене откроется без стилей и с битыми ссылками.

## Шаг 8. Привязать домен к бэкенду

1. Render → сервис `memex-api` → **Settings → Custom Domains → Add**
   → `api.memexdex.com`
2. Обновить две переменные:

   **На Render** (Environment):
   ```
   CORS_ORIGINS = https://memexdex.com,https://www.memexdex.com
   ```

   **На GitHub** (Actions → Variables):
   ```
   NEXT_PUBLIC_API_URL = https://api.memexdex.com/api/v1
   ```

3. **Actions → Deploy web to GitHub Pages → Run workflow**

   Пересборка обязательна: адрес API вшивается в файлы при сборке,
   перезапуском его не поменять.

## Шаг 9. Проверить

```bash
curl https://api.memexdex.com/health

curl -I -H "Origin: https://memexdex.com" \
  https://api.memexdex.com/health | grep -i access-control
```

Открыть `https://memexdex.com` — сайт должен выглядеть так же, как
раньше на github.io.

# Если что-то не работает

| Симптом | Причина |
|---|---|
| Сайт открылся, но пустые экраны | `CORS_ORIGINS` не совпадает с адресом сайта |
| Всё в 404 после привязки домена | не задана `PAGES_CUSTOM_DOMAIN` |
| Первый запрос висит минуту | Render проснулся после сна — это нормально |
| «API не отвечает» | сервис на Render упал, смотрите его логи |
| Запросы уходят в localhost | не задана `NEXT_PUBLIC_API_URL` либо не пересобран фронт |
| Домен не проверяется в GitHub | DNS ещё не разошёлся, подождите до часа |
