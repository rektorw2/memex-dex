# Бесплатное развёртывание: GitHub Pages + Render + Neon

Раскладка:

| Часть | Где | Бесплатно | Ограничение |
|---|---|---|---|
| Фронтенд | GitHub Pages | бессрочно | только статика |
| API + воркеры | Render (free) | бессрочно | засыпает через 15 мин простоя |
| Postgres | Neon (free) | бессрочно | 0.5 ГБ, лимит соединений |

Итоговый адрес: `https://rektorw2.github.io/memex-dex/`

Главное ограничение — сон Render. После простоя первый запрос ждёт около
50 секунд, и выглядит это как поломка. Для демонстрации приемлемо, для
торговли нет: задержка на входе в позицию — это проскальзывание.

---

## 1. Проверить сборку локально

Прежде чем что-то публиковать, убедитесь, что статический экспорт
собирается. Это единственный шаг, который нельзя проверить заранее.

```bash
npm test
DEPLOY_TARGET=pages GITHUB_REPOSITORY=rektorw2/memex-dex npm run build -w @memex/web
ls apps/web/out
```

Должна появиться директория `apps/web/out` с `index.html` внутри.

## 2. Репозиторий

```bash
cd memex-dex
git init -b main
git add .
git commit -m "Memex DEX: торговый терминал, коллы, копитрейдинг"
```

Перед первым пушем убедитесь, что секреты не уехали в репозиторий:

```bash
git ls-files | grep -E '^\.env$' && echo "ОСТАНОВИТЕСЬ: .env в индексе" || echo "секреты не попали"
```

Создать репозиторий и запушить:

```bash
gh repo create memex-dex --private --source=. --push
```

Если пуш отклонён с текстом `refusing to allow an OAuth App to create or
update workflow ... without workflow scope` — у токена `gh` нет права на
запись файлов в `.github/workflows/`. Репозиторий при этом уже создан,
достаточно расширить права и повторить пуш:

```bash
gh auth refresh -h github.com -s workflow
git push -u origin main
```

## 3. База данных: Neon

1. [neon.tech](https://neon.tech) → создать проект, регион `eu-central-1`
   (тот же, что у Render — иначе каждый запрос теряет время на трансатлантику)
2. Скопировать **pooled** connection string — в имени хоста есть `-pooler`.
   Прямое подключение на бесплатном тарифе быстро упирается в лимит
   соединений, и API начнёт отваливаться под нагрузкой.
3. Строка должна оканчиваться на `?sslmode=require`

Применить схему и залить тестовые данные:

```bash
DATABASE_URL="<строка из Neon>" npm run db:push
DATABASE_URL="<строка из Neon>" npm run db:seed
```

## 4. API: Render

Dashboard → **New → Blueprint** → выбрать репозиторий. `render.yaml`
уже в проекте, Render поднимет сервис сам.

Вручную задать три переменные (помечены `sync: false`):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | pooled-строка из Neon |
| `CORS_ORIGINS` | `https://rektorw2.github.io` |
| `ZEROX_API_KEY` | можно оставить пустым — нужен только для BNB/EVM |

`CORS_ORIGINS` указывается **без пути к репозиторию**: браузер передаёт
в заголовке `Origin` только схему и хост. Значение
`https://rektorw2.github.io/memex-dex` не совпадёт ни с чем, и все запросы
будут заблокированы.

Проверка после деплоя:

```bash
curl https://memex-api.onrender.com/health
# {"ok":true,"mode":"paper",...}
```

## 5. Фронтенд: GitHub Pages

В репозитории: **Settings → Pages → Source → GitHub Actions**.

Затем **Settings → Secrets and variables → Actions → Variables → New**:

```
NEXT_PUBLIC_API_URL = https://memex-api.onrender.com/api/v1
```

Это переменная времени сборки: Next вшивает её в бандл. После любого
изменения адреса API нужно пересобрать фронтенд — перезапуск не поможет.
Пересобрать вручную: вкладка **Actions → Deploy web to GitHub Pages →
Run workflow**.

Дальше каждый пуш в `main` публикует новую версию автоматически.

## 6. Проверка, что всё сошлось

```bash
# API жив
curl https://memex-api.onrender.com/health

# CORS настроен: заголовок должен присутствовать
curl -I -H "Origin: https://rektorw2.github.io" \
  https://memex-api.onrender.com/health | grep -i access-control-allow-origin
```

Если второй запрос ничего не выводит — фронтенд будет получать пустые
экраны, а в логах API при этом будет тишина. Это самая частая причина
«ничего не работает, но ошибок нет».

Открыть `https://rektorw2.github.io/memex-dex/` и войти как
`admin@memex.local`. Пароль сид напечатал в консоли на шаге 3 — при
подключении к Neon он генерируется случайно и нигде не сохраняется.
Задать свой заранее: `SEED_PASSWORD=... npm run db:seed`.

Первый вход после простоя займёт около минуты — Render будит контейнер.
Интерфейс покажет об этом подсказку вместо ошибки.

## Что дальше стоит поменять

**Пароли.** Для облачной базы сид генерирует случайный пароль и печатает
его один раз — в репозитории его нет. Если задавали `SEED_PASSWORD`
вручную, не коммитьте его.

**Свести к минимуму публичность.** Пока приложение в paper-режиме, риска
для средств нет. Но витрина с коллами и статистикой доходности,
доступная из интернета, — это уже публичное предложение. Стоит прочитать
`LEGAL-RISK.md` до того, как давать ссылку кому-то, кроме себя.

**Убрать сон.** Если сервис нужен постоянно доступным — Render Starter
($7/мес) или Fly.io, который не засыпает на бесплатном тарифе.
Пинговать спящий сервис по расписанию — против правил Render.
