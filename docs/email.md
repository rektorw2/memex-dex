# Доставка писем

Письмо в проекте сейчас одно: код подтверждения адреса. Оно
обязательное — без подтверждённого адреса не выдаётся бесплатный
период, а без него человек не видит продукт. Поэтому неработающая
доставка равна неработающей регистрации, и настраивать её нужно
до открытия доступа, а не после.

## Устройство

Три слоя, разделённые намеренно.

| Слой | Файл | Знает про |
| --- | --- | --- |
| Правила кода | `packages/core/src/email-verification.ts` | срок, попытки, паузу |
| Текст письма | `packages/core/src/email-message.ts` | тему и содержание |
| Транспорт | `apps/api/src/services/mailer.ts` | провайдера, ключ, сеть |

Правила и текст не знают, кто доставляет письмо. Провайдера меняют
по причинам, к подтверждению адреса отношения не имеющим — цена,
доставляемость, страна, — и менять вместе с ним правила проверки кода
не должно быть нужно.

Провайдерский код целиком лежит в одном файле. Resend вызывается
напрямую через HTTPS, а SMTP работает через `nodemailer`: протокол
содержит TLS, авторизацию, несколько фаз ответа и таймауты, поэтому
писать собственный SMTP-клиент здесь было бы лишним риском.

## Транспорты

| `EMAIL_PROVIDER` | Что делает | Где допустим |
| --- | --- | --- |
| `disabled` | Отвечает отказом `EMAIL_DELIVERY_UNAVAILABLE` | везде, по умолчанию |
| `console` | Пишет в журнал вместо отправки, код возвращается в ответе API | только вне production |
| `resend` | Отправляет через api.resend.com | везде |
| `smtp` | Отправляет через TLS SMTP, включая Gmail | везде |

**`disabled` — это отказ, а не тишина.** Приложение, поднятое без
настроек, честно говорит «доставка не настроена», и интерфейс
показывает это словами. Молчаливый успех был бы хуже всего: человек
ждал бы письма, а мы считали бы, что отправили.

**`console` в production запрещён.** Приложение не стартует: этот
транспорт пишет письмо в журнал, то есть код не получит никто,
а API отчитается об успехе.

## Переменные окружения

Resend с подтверждённым доменом:

```env
EMAIL_PROVIDER=resend
EMAIL_FROM=Memex DEX <no-reply@ваш-домен>
RESEND_API_KEY=...
PUBLIC_APP_NAME=Memex DEX
PUBLIC_APP_URL=https://ваш-домен
```

`EMAIL_PROVIDER=resend` без `RESEND_API_KEY` или без `EMAIL_FROM` —
ошибка при старте. Обнаружить несогласованные настройки лучше сразу,
чем по жалобе человека, который ждёт код десять минут.

Gmail для первого запуска без собственного почтового домена:

```env
EMAIL_PROVIDER=smtp
EMAIL_FROM=Memex DEX <ваш-адрес@gmail.com>
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=ваш-адрес@gmail.com
SMTP_PASS=16-значный-пароль-приложения
PUBLIC_APP_NAME=Memex DEX
PUBLIC_APP_URL=https://rektorw2.github.io/memex-dex/
```

`SMTP_PASS` — не основной пароль Google. Это отдельный пароль
приложения, созданный после включения двухэтапной проверки. Он хранится
только в секретах Render и может быть отозван отдельно, не меняя пароль
аккаунта. Приложение не стартует, если выбран `smtp`, но отсутствует
хост, пользователь, пароль приложения или отправитель.

## Что должен сделать владелец проекта

Для текущего запуска через Gmail:

1. Включить двухэтапную проверку Google.
2. Создать отдельный пароль приложения с названием `Memex DEX`.
3. В Render добавить `EMAIL_PROVIDER=smtp`, адрес Gmail и SMTP-настройки
   из примера выше. Пароль приложения вставляется только в `SMTP_PASS`.
4. Перезапустить сервис и пройти живой сценарий: запросить код, получить
   письмо, ввести код и включить бесплатный период.
5. Отправить тесты на Gmail и ещё один почтовый сервис и проверить папку
   «Спам». Личный Gmail подходит для небольшого запуска, но не заменяет
   транзакционный сервис при росте.

Для постоянной отправки от имени продукта нужен собственный домен:
добавить его в Resend, настроить SPF, DKIM и DMARC, создать ключ с правом
отправки и переключить `EMAIL_PROVIDER=resend`. Секреты в репозитории
не хранятся ни для одного транспорта.

## Что происходит при сбое

Порядок шагов выдачи кода выбран так, чтобы сбой не оставлял следов.

1. Проверяется транспорт. Не настроен — код не создаётся вовсе,
   иначе пауза повторной отправки оказалась бы занята письмом,
   которого нет.
2. Занимается слот — одним запросом к базе, с условием «паузы нет
   или она прошла». Два одновременных запроса не могут пройти оба:
   письмо уходит одно, и годен именно его код.
3. Отправляется письмо. Провайдер отказал или не ответил — слот
   освобождается, и повторить можно немедленно. Ответ содержит
   `retryAfterSeconds: 0`: ждать не за что, письма не было.

Единственный случай, когда код остаётся в базе без письма, — падение
процесса между шагами 2 и 3. Тогда человек ждёт минуту и повторяет.

## Что в письме

Код, срок действия и строка о том, что делать, если письмо
не запрашивали. Ссылок нет вовсе: письмо с кодом читает в том числе
тот, кто получил чужой ящик, и ссылка, делающая что-то по нажатию,
превратила бы его в дверь. Предложений и обещаний тоже нет — письмо
с кодом читают три секунды, и всё лишнее мешает найти цифры.

## Чего в журналах не бывает

Кода, хеша кода, ключа провайдера и полного адреса. Адрес пишется
в виде `m***@e***.com`: для разбора инцидента этого достаточно,
а полный адрес осел бы в файлах, в системе сбора логов и в резервных
копиях навсегда. Тема письма в журнал не попадает тоже — в ней стоит
код.
