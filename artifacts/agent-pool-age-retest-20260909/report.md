## Воспроизведённый обход общего лимита

Аудит прямых обращений к Gecko обнаружил второй клиент в `services/token-intel.ts`: запрос `/tokens/.../info` для описания и соцсетей шёл через самостоятельный `fetch`, минуя общий PostgreSQL gate и обработку Retry-After.

Два новых поведенческих теста на прежнем коде упали:

1. После 429 другого клиента запрос социальных фактов всё равно выполнялся: **2 HTTP-вызова вместо 1**.
2. После 429 самого клиента социальных фактов срочные метаданные получали **accepted вместо waiting_capacity**; пауза не сохранялась для другого экземпляра сервиса.

[Исходный провал](logs/social-budget-repro.log) сохранён без изменения. Наличие этого обхода доказано тестом, но его участие именно в production-отказе STEPZ по имеющимся логам не доказано. Внешняя квота/IP и нагрузка вне приложения также не измерялись.

Исправление: общий HTTP-клиент `fetchGeckoJson` из `market-data.ts` используется и для социальных фактов. Теперь эти запросы учитывают тот же общий бюджет, приоритет метаданных и сохранённую паузу после 429. Все прямые обращения к Gecko в исходниках API проходят через этот клиент. Клиент GoPlus не изменён. Сбор социальных фактов теперь может ждать фонового слота дольше; он не должен расходовать неучтённую квоту в ущерб возрасту пула.

## Проверка настоящим сервисом и базой

Сохранённый ответ STEPZ перенесён в штатную fixture. Новый `pool-age-production-replay.e2e.test.ts` использует настоящие worker, metadata service, HTTP parser и PostgreSQL; подменяется внешний HTTP-ответ и готовность сетей. Для повторяемости временные отметки ответа сдвигаются относительно текущего времени базы с сохранением исходного возраста пула и задержки доставки. На production фиктивные сигналы не создавались.

Подтверждены:

- успешный ответ STEPZ → точная дата записана в Token → допустимый возраст → ровно один PAPER-вход;
- общий 429 на 60 секунд → ожидание ёмкости → истечение исходного срока → окончательный пропуск;
- позднее появление даты и повторная доставка не переоткрывают пропущенный сигнал;
- 429 от социальных фактов сохраняется в настоящей PostgreSQL и учитывается сервисом метаданных после перезагрузки модуля.

Ни возрастной фильтр, ни 30-секундный срок, ни порог $600 не ослаблялись. Исторические production-решения не менялись.
