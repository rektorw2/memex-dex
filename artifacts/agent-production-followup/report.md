# Production follow-up: результат для ревью

Работа поверх HEAD `619e631` и существующего diff. Коммит, push, публикация, изменение production-настроек, ключей и реальные сделки не выполнялись. Чужие отчёты сохранены. Новый план ниже заменяет ошибочную рекомендацию предыдущего отчёта удалять историю миграций и таблицы.

## Изменения

### Возраст до окончательного решения

Приёмник `ingestOkxSignal` атомарно записывает Token и OkxSignal и сразу передаёт сигнал агенту. Он не получает дату пула. Ранее `decideRun` читал `Token.poolCreatedAt=null` и окончательно пропускал сигнал. Отдельный `token-importer` раз в час заполняет дату из `NormalizedToken.firstTradeAt` (OKX hot-token) либо `pool_created_at` (GeckoTerminal). Это объясняет возможность позднего появления даты. **Точный источник и момент записи прошлой даты Mooncoin в базе не сохранены; эта итерация не выдаёт предположение за измерение production.**

Теперь потенциально подходящий сигнал с неизвестной датой сохраняет `RECEIVED / WAITING_FOR_TOKEN_METADATA`. Окно — не более 30 секунд от **сохранённого receivedAt**, причём дедлайн стратегии (30 секунд от signaledAt) продолжает действовать. Решения по сумме/типу/неподдерживаемой сети не задерживаются ради метаданных. После даты заново выполняется полный допуск, включая возраст, свежесть и цену, а воркер перечитывает контроль и готовность сети/источника. При истечении окна — окончательный пропуск; поздние метаданные не меняют завершённые решения.

Однократный условный переход run с `decisionCode=null` запускает получение даты через уже существующий `fetchPoolForToken`. Это **метаданные пула GeckoTerminal, не новый источник сигналов и не источник цены входа**. Сохраняется только валидный `pool_created_at`, только в пустое поле и для совпадающих tokenId/chain/address. Не используются `firstSeenAt`, время импорта или время создания контракта. Все сигналы по-прежнему поступают исключительно из официального OKX Signal API.

Ограничения нагрузки: максимум два незавершённых запроса, максимум один запуск за пять секунд на процесс, дедупликация по токену на минуту, без дополнительной очереди. Запрос не блокирует проход агента; общий провайдер имеет собственные ограничитель и HTTP timeout. Условный переход run хранится в PostgreSQL и не переисполняется после рестарта. Восстановление читает также `RECEIVED`; уникальность `(signalId,strategyId)` и атомарное открытие сохранены. TEST_HARNESS не обращается за внешними метаданными.

Если провайдер не знает пул (в частности, текущий Gecko-адаптер не поддерживает Robinhood), агент ждёт общий Token cache до дедлайна, затем пропускает. Наличие метаданных для каждого нового токена не гарантируется. Исторические решения не пересчитаны; исторические сигналы не получают нового окна свежести.

### WS и REST

Подтверждённый production-ответ **60036** классифицируется как недоступность WebSocket для ключа по **Market API subscription**. Сохраняется официальный Signal REST. После отказа быстрые переподключения прекращаются: повтор доступа через час; также предусмотрен явный метод `retrySignalAccess()` для контролируемого повторного запроса. Stop отменяет таймер. Успешный login сам по себе не подтверждает подписку; восстановление фиксируется только после subscribe acknowledgement, событие учитывается отдельно. Отрицательное subscribe acknowledgement не считается успехом.

На экране раздельно видны login, подписка, время события WS, ответ/ошибка REST, следующий повтор доступа и две задержки последнего решения: доставка от OKX и решение после получения. Во время работающего REST выключенный WS не изображается как полное отсутствие связи. Отказ обоих транспортов сохраняет паузу новых входов; сопровождение открытых позиций остаётся отдельным процессом. Настоящее восстановление WS на production **не подтверждено**.

### Сети и правила

Проверены приём REST-сигнала, нормализация 501/56/4663, официальное тело Market price, положительные котировки на фикстурах, RPC chainId для EVM и решения всех пяти стратегий с сетевыми моделями расходов. EVM-адреса в запросе цены приводятся к нижнему регистру, регистр Solana сохраняется.

Живые списки Signal/Market теперь истекают через 65 минут, RPC-подтверждение — через 10 минут, даже если фоновый цикл перестал выполняться. Пересекающиеся проходы REST исключены. До первого ответа прежнее различие «документированная поддержка / подтверждено живым ответом» сохранено; истёкшее подтверждение уже не превращается в доверие документации. Модели расходов — консервативные PAPER-оценки, не измеренные комиссии исполнения LIVE.

Это не новый снимок сервера: production в этой итерации не проверялся. Перед любым будущим production-тестом необходимо перечитать `PaperAgentControl` и текущие runtime/source/network-состояния; прежнее включённое состояние не предполагается.

Baseline остаётся $600, исторические shadow-стратегии сохранены. Semi-auto допускает только неизменённый TARGET; auto — все пять режимов. LIVE/BROADCAST_LOCKED не разблокированы.

### Наблюдатель и Render

`node scripts/agent-observation.mjs FILE.csv` проверяет упорядоченные timestamps, покрытие ≥24 часов, интервалы ≤90 секунд, отсутствующие метрики, реальные длительности ошибок и несовпадения uptime с прошедшим временем. Сбросы uptime исключают PASS. Окна RSS — первые/последние шесть часов, медианы взвешены временем. Здоровье воркера и доступность источника имеют отдельные вердикты; общий PASS требует обоих. Две записи через сутки и частые рестарты дают NOT_CONFIRMED. Старый путь summarize-24h.sh теперь вызывает исправленную реализацию. Выход NOT_CONFIRMED возвращает ненулевой код.

`render.yaml` приведён к выбранным владельцем 1 CPU / 2 ГБ: **`1c-2g`**, согласно [Render Blueprint reference](https://render.com/docs/blueprint-spec#plan). Убраны устаревшие комментарии про минимальный план и $7. Blueprint не применялся.
