# Проверка владельцем доступа OKX Signal WebSocket

Подтверждённый ответ production-ключа из предыдущей проверки: login `code=0`, затем `60036 — WebSocket access requires an active Market API subscription.` Он говорит о доступе этого ключа, а не доказывает отсутствие оплаты вообще.

1. В Render открыть **memex-api → Environment** и сверить идентичность активного `OKX_API_KEY` и, если задан, `OKX_PROJECT_ID`. Делать это приватно: не копировать ключ, secret или passphrase в отчёт, чат или скриншот.
2. Открыть [OKX OnchainOS Developer portal](https://web3.okx.com/onchainos/dev-portal) под владельцем именно этого ключа. Найти ключ в его проекте и сопоставить его с Render, а не только название аккаунта или похожего проекта.
3. В управлении **Market API subscription** этого аккаунта/проекта проверить статус active, срок действия, привязку подписки к проекту и право ключа на WebSocket. Сверить назначение платежа с тем же проектом. Баланс, свободная REST-квота и отдельная оплата REST не являются подтверждением подписки WS. Официальная [таблица Market API](https://web3.okx.com/onchainos/dev-docs/market/market-api-fee) отдельно указывает доступность WebSocket для уровней подписки.
4. Если подписка активна у нужного проекта, но ключ продолжает получать 60036, передать поддержке OKX идентификатор проекта, время отказа и название канала `dex-market-new-signal-openapi`, без secret/passphrase. Попросить проверить entitlement ключа. Канал нельзя заменять потоком сделок кошельков.
5. После подтверждения исправления доступа наблюдать новый цикл login → subscribe acknowledgement → настоящее событие. Новая версия автоматически повторяет доступ раз в час. Один login или открытый TCP-сокет не означает исправленный WS. Отдельно проверить работающий Signal REST и задержки доставки/решения.

Фактическая платёжная запись и авторизованная страница владельца в этой итерации не открывались. Тариф не покупался, ключи не менялись, сообщений поддержке не отправлялось.
