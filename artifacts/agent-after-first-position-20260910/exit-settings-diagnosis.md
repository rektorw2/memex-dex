# Исчезнувшие правила выхода в форме

Read-only проверка production 2026-09-10T01:52:50.883Z:

- `PaperAgentControl.isEnabled=true`, updatedAt `2026-09-10T01:50:05.090Z`.
- `LIVE_AGENT_CONTROL_MODE=semi-auto`.
- Рабочий счёт, созданный `2026-09-08T23:35:11.720Z`, сохранил `policySnapshot.exitPlan.mode=TRAILING_PURE`: trailingPct=50, trailingAfterLeg=0, legs=[{sellPct:50,multiple:2}], breakevenAfterLeg=1, maxHoldMs=21600000. Включение агента этот план не изменило.

Причина отображения: `/paper-agent` возвращает phase4.allowedExitModes из LIVE_AGENT_CONTROL_MODE. Settings формы PAPER фильтрует карточки по этому списку, а useEffect автоматически выбирает первый разрешённый вариант вместо сохранённого, если сохранённый больше не разрешён. Административный API настройки PAPER применяет то же ограничение. Поэтому отображаются одновременно «сейчас: Чистый трейлинг» и выбранная для новой настройки «Цель 2×». Сам просмотр ничего не записывает; нажатие «Применить» создаёт новый счёт с выбранным планом.

В существующем core явно задокументировано прежнее решение владельца: semi-auto только TARGET без override; auto все пять. Дополнительно env запрещает запуск сервера с LIVE_AGENT_CONTROL_MODE=auto. Просто переключить production в auto нельзя: сервер не запустится.

Проверка страницы: 83 теста passed (`npm run test -w @memex/web -- app/agent/agent-page.test.tsx`), включая существующий тест скрытия остальных правил и автоматического выбора TARGET в semi-auto.

Исполняемый код и production-настройки этой диагностикой не изменялись. Пользователю направлено уточнение, нужно ли разрешить все пять правил отдельно для PAPER с сохранением ограничений LIVE: это меняет ранее подтверждённое ограничение PAPER, поэтому решение не принято автоматически.
